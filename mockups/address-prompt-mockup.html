ADDRESS PROMPT — MOCKUP

When a printer has been unreachable for 30 seconds, its panel stops cycling and asks. OUTPOST-02 shows the question. SCOUT-03 shows what happens after someone taps AUTO-FIND, or after the countdown runs out with nobody around: the console searches, and the panel still offers ENTER ADDRESS. A white NEEDS ADDRESS chip in the status bar flags it fleet-wide. White is used because this is an indicator, not an alarm; red stays reserved for errors. Tap ENTER ADDRESS on either panel.

The dialog is interactive. Type with the keypad, or with a keyboard if one is attached, and tap CONNECT. The console tests the address before accepting it by logging in with this printer's own access code, so a typo can't point it at the wrong printer. Simulated outcomes: 192.168.1.73 connects; 192.168.1.80 is a different printer; any other valid address has nothing answering.

Where this fits relative to v1.7 rediscovery, plus three choices for you.

1 CONNECTION DROPS — paho retries the same address on its own (unchanged)
2 STILL DOWN AFTER 30 S (discovery.rediscover_after_s) → panel ASKS: ENTER ADDRESS / AUTO-FIND
   · an SSDP announcement can still arrive in the meantime and fix it silently
3a ENTER ADDRESS → console tests it (MQTT login with the access code) → on success, reconnects and saves it
3b AUTO-FIND tapped, or nobody answers in 2 min → v1.7 rediscovery runs unchanged (SSDP search → subnet scan, max 3 empty scans)
4 ENTER ADDRESS / SET ADDRESS… stays available the whole time

CHOICE 1 · IF NOBODY ANSWERS

Recommended: auto-find after 2 minutes. The wall display is often unattended overnight or over a weekend. A printer whose lease renews at 2 a.m. would otherwise sit offline until someone walks by.

Alternative: wait indefinitely for a person. Auto-discovery then runs only when someone taps AUTO-FIND. The countdown line disappears.

CHOICE 2 · REMEMBER THE ADDRESS

Recommended: write it into config.json (that printer's ip), keeping a config.json.bak. A restart then uses the new address. A checkbox in the dialog, default on, allows a one-off.

Alternative: this session only. A restart reverts to the old address.

CHOICE 3 · AT STARTUP

Recommended: same rule. A printer listed with no ip (or a stale one) that hasn't connected 30 s after startup gets the same prompt. The auto-find countdown still applies, so a printer with no ip is found on its own as today.

Alternative: prompt only after a printer that was connected drops, and keep today's behavior at startup.

NO DECISION NEEDED

Address entry goes through set_ip(), the same path as discovery, so _run() stays the only place a client is created. The test login means an address can only be accepted if the printer there knows this printer's access code. The console has no login, so anyone on the LAN could open the dialog, but they couldn't point a panel at a non-printer. Demo printers get a simulated dialog.
