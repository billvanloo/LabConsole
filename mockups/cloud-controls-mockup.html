CLOUD-MODE PRINTERS — DETAIL VIEW CONTROLS

A printer marked "cloud": true in config.json refuses pause, resume, stop and start print from the console (Authorization Control: mqtt message verify failed), so those buttons go. The light works and stays. The fleet panels have no controls and don't change. In both options the header gets a small CLOUD tag beside the model, and a line under the buttons says where those controls live instead. The only difference is what happens to START PRINT…: uploading still works in cloud mode, and an X1C or H2D can start a file from its own screen (Files), so option A keeps an upload-only dialog.

BEHIND THE SCENES (BOTH OPTIONS)

  • config.json: "cloud": true on a printer. Missing or false keeps today's controls, so existing configs don't change until you add it.
  • The server refuses pause / resume / stop / start print for a cloud printer before they reach it, and logs why. A stale browser tab or a script can't send them and set off the printer's verification-failed alert.
  • Docs: the Operator Guide's detail-view section and the Admin Guide's config table and cloud-mode notes. The PDF is regenerated.
