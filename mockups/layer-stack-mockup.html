Each block is one layer. Completed layers stack bottom-up, left to right as glowing cyan blocks; the layer being printed glows and pulses in the alternate color with a dashed outline, as in the sketch. When a layer finishes it flashes and settles into the stack. The dashed rounded rectangle is the whole job: its size is fixed by the total layer count, so the empty space inside shows what's left. Above about 600 layers the blocks would get too small to read, so each block stands for several layers and a chip says so. Try 1400 to see it.

CHOICE 1 · CURRENT-LAYER COLOR

Green follows the sketch and stands out against the cyan stack. Amber is already the console's "printing" color, so it would match the panel lamp and add no new color meaning. While paused, the current block turns violet and stops pulsing, to match the paused lamp.

CHOICE 2 · ONE BLOCK PER LAYER, OR BUCKETS

It stays one block per layer until blocks would fall below about 7 px on the 7″ panel; past that, each block covers several layers and the 1 BLOCK = N LAYERS chip appears. Fine-detail prints at 0.08 mm can pass 1,000 layers, so some fallback is needed. The other option is to always use one block per layer and accept a fine grain.

CHOICE 3 · GHOST SLOTS

Faint outlines mark the layers still to come. They make progress readable from across the room but add visual noise. The sketch doesn't have them. Default on in this mockup; toggle to compare.

INTEGRATION NOTES · NO DECISION NEEDED

Layer data only exists while printing or paused, so this face replaces the resting animation in those states only; idle printers keep the radar and orbit. The stack is drawn to a cached canvas and redrawn only when a layer finishes; each frame only redraws the current block and the border, which keeps the Pi 3 comfortable. Adopting it means the docs' "resting faces carry no data" line changes.
