ADMIN GUIDE

SETUP, CONFIGURATION, AND CARE OF THE CONSOLE

01 PRINTER PREREQUISITES

Repeat on each printer before adding it to the console:

  1. Update to recent firmware.
  2. On the printer screen, switch to LAN Only Mode and enable Developer Mode (Settings → General/Network). Developer Mode opens the local MQTT, live-stream, and FTP channels the console uses. Note that Developer Mode printers cannot simultaneously connect to Bambu Cloud.
  3. Record the Access Code (Settings → Network) and Serial Number (Settings → Device).
  4. X1-series / H2D only: enable LAN Mode Liveview so the RTSPS camera stream is available.
◈ NOTE

Regenerating a printer’s access code invalidates the one in config.json — the panel will go OFFLINE until the config is updated.

02 INSTALLATION

sudo apt update && sudo apt upgrade -y
sudo apt install -y git python3-venv ffmpeg
#   (ffmpeg is only needed for X1/H2D cameras)
git clone https://github.com/billvanloo/LabConsole.git /home/pi/lab-console
cd /home/pi/lab-console
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp config.example.json config.json
nano config.json              # fill in serials + access codes
.venv/bin/python server.py    # open http://<pi-address>:8080

To evaluate without printers, run .venv/bin/python server.py --demo — no config file is required.

◈ WHY A VIRTUAL ENVIRONMENT

Current Raspberry Pi OS (Bookworm and later) and Ubuntu 23.04+ refuse a plain pip3 install with error: externally-managed-environment, to keep pip from overwriting packages the OS depends on. The .venv folder holds the console’s own copies of its libraries instead. Always start the console with .venv/bin/python — plain python3 won’t see those libraries. The systemd unit already does this.

◈ NOTE

The paths above and in lab-console.service assume the user pi. Newer Raspberry Pi OS images have no default pi account — if you chose a different username, substitute it for pi in /home/pi/lab-console here and in the service file’s User=, WorkingDirectory= and ExecStart= lines.

RUNNING ON UBUNTU / OTHER LINUX HOSTS

The console runs unchanged on a standard Ubuntu machine (desktop or server) instead of a Raspberry Pi — nothing in the code is Pi-specific. Install the same way:

sudo apt update && sudo apt upgrade -y
sudo apt install -y git python3-venv ffmpeg
git clone https://github.com/billvanloo/LabConsole.git ~/lab-console
cd ~/lab-console
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

A few environment differences to check:

  • Firewall — Ubuntu often runs ufw, which Raspberry Pi OS does not enable by default. Allow the console’s port: sudo ufw allow 8080/tcp.
  • Same LAN as the printers — SSDP discovery is a passive listener; the host must sit on the same network segment as the printers, not behind a router hop or separate VLAN.
  • Laptops — Wi-Fi power-saving can drop the idle discovery socket or let the machine sleep. Disable suspend and Wi-Fi power management, or use a wired/always-on machine.
◈ NOTE

A typical Ubuntu machine has far more headroom than a Pi 3 — camera.max_streams in the config can safely be raised above 1 if you want multiple live camera views at once.

03 CONFIG REFERENCE

PER PRINTER

FIELDMEANING
idShort unique key; used in URLs.
nameDisplay name on the dashboard.
modelDisplay label (X1 CARBON, H2D, A1 MINI, …).
serialPrinter serial number — used for MQTT topics and SSDP matching.
access_codeLAN access code from the printer screen.
ipOptional. SSDP discovery fills and updates it automatically; a static or DHCP-reserved address makes startup instant.
camerartsp for X1-series and H2D, chamber for A1 / A1 Mini / P1-series, none to disable.

GLOBAL

FIELDDEFAULTMEANING
http_port8080Port the console serves on.
max_upload_mb200Upload size limit for .3mf files.
camera.max_streams1Concurrent camera relays. Keep at 1 on a Pi 3; a Pi 4/5 can take more. A new viewer evicts the oldest when the limit is hit.
camera.rtsp_fps8Relay frame rate for RTSPS cameras (transcode cost knob).
camera.rtsp_width640Relay width for RTSPS cameras.
sdcard_url_basefile:///sdcard/Path base for start-print. Switch to file:///mnt/sdcard/ if newer firmware reports file-not-found.

04 RUN AT BOOT / KIOSK DISPLAY

sudo cp lab-console.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now lab-console
# logs:
journalctl -u lab-console -f

For a dedicated wall display, point a kiosk browser at the console, e.g. chromium-browser --kiosk http://localhost:8080. The frontend pauses its panel cycling while the browser tab is hidden, so an always-on display costs the Pi almost nothing when nobody is looking at it.

05 TROUBLESHOOTING

SYMPTOMLIKELY CAUSE / FIX
Panel OFFLINEPrinter unreachable over MQTT. Check power, LAN, Developer Mode, and that the access code matches. If IPs changed, discovery re-finds printers within a minute of their next announcement.
X1/H2D camera NO SIGNALLAN Mode Liveview disabled, or ffmpeg not installed. Some H2D firmware versions have temporarily shipped without local liveview pending updates — status and control keep working.
A1 camera is ~1 fpsThat is the chamber camera’s hardware rate, not a fault.
Start print: file not foundSwitch sdcard_url_base to file:///mnt/sdcard/.
SD list emptyOnly files in the SD card root are listed; uploads also go to the root.
pip3 install fails: externally-managed-environmentThe OS blocks system-wide pip installs. Create the virtual environment and install into it: python3 -m venv .venv, then .venv/bin/pip install -r requirements.txt. If venv is missing, sudo apt install python3-venv.
ModuleNotFoundError: aiohttpStarted with plain python3 instead of .venv/bin/python.
LINK red in the status barBrowser lost its WebSocket to the Pi; it reconnects automatically. If persistent, check the service with journalctl.
▲ SECURITY

The console has no login and printer access codes live in config.json. Keep it on a trusted LAN/VLAN and don’t expose port 8080 to the internet.
