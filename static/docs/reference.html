TECHNICAL REFERENCE

PROTOCOLS, SCHEMAS, AND THE HTTP API

The printer-side protocols below are the community-documented LAN Developer Mode interfaces (see the OpenBambuAPI project and the Bambu Lab wiki’s third-party integration page). Nothing here uses Bambu Cloud.

01 MQTT (STATUS + CONTROL)

One TLS connection per printer to port 8883, username bblp, password = the printer’s access code, self-signed certificate accepted. The console subscribes to the report topic and publishes commands to the request topic:

device/<SERIAL>/report    ← status pushes (partial JSON, merged client-side)
device/<SERIAL>/request   → commands

Commands the console sends (each carries a sequence_id):

ACTIONPAYLOAD (ABBREVIATED)
full refresh{"pushing":{"command":"pushall"}}
pause / resume / stop{"print":{"command":"pause"|"resume"|"stop","param":""}}
chamber light{"system":{"command":"ledctrl","led_node":"chamber_light","led_mode":"on"|"off",…}}
start print{"print":{"command":"project_file","url":"file:///sdcard/<file>.3mf","param":"Metadata/plate_1.gcode","use_ams":true,…}}

Report fields the console reads: gcode_state (RUNNING / PREPARE / PAUSE / IDLE / FINISH / FAILED), mc_percent, mc_remaining_time, layer_num / total_layer_num, subtask_name / gcode_file, nozzle/bed/chamber temperatures and targets, cooling_fan_speed, spd_lvl_name, lights_report, AMS tray types and colors, and hms / print_error for the ERROR state.

02 CAMERA PROTOCOLS

MODELSTRANSPORTCONSOLE RELAY
X1 / X1C / X1E / H2D RTSPS on port 322, URL rtsps://bblp:<code>@<ip>:322/streaming/live/1. Requires LAN Mode Liveview. ffmpeg transcodes to MJPEG at a configurable fps/width; frames are re-served as multipart/x-mixed-replace.
A1 / A1 Mini / P1 Proprietary chamber-image service, TLS on port 6000. An 80-byte auth packet (username + access code) is sent; the printer then streams length-prefixed JPEG frames at ~1 fps. Frames pass straight through to the same MJPEG endpoint — no transcoding.

The relay hub enforces camera.max_streams (default 1): a new viewer evicts the oldest active relay. The frame queue is depth-2 and drops old frames, so a slow client sees the latest image rather than building latency.

A chamber camera needs roughly three seconds to hand over its first frame, so the hub keeps the newest frame per printer and replays it the instant a viewer connects, then overwrites it from the live stream. The replay is skipped once that frame is more than 30 seconds old, so the first image you see is never badly stale.

03 FTPS + DISCOVERY

FTPS — implicit TLS on port 990, user bblp. Used to list .3mf/.gcode files in the SD root (MLSD, with NLST fallback) and to upload new files ahead of a project_file command.

SSDP discovery — the console passively listens on UDP ports 2021 and 1990 for the printers’ periodic announcements, matching on the serial in USN and reading the address from Location. When a printer’s address changes, its MQTT client reconnects to the new one. If Bambu Studio runs on the same host and holds the port, discovery is skipped silently and configured IPs are used.

04 WEBSOCKET SCHEMA

Browsers connect to /ws. The server pushes the full fleet snapshot whenever anything changes (checked at 1 Hz):

{ "type":"fleet", "version":123, "demo":false, "printers":[ {
    "id":"voyager01", "name":"VOYAGER-01", "model":"X1 CARBON",
    "state":"printing",            // idle|printing|paused|error|offline
    "online":true, "camera":"rtsp",// rtsp|chamber|demo|none
    "file":"bracket_v3.3mf", "percent":62, "remaining_min":107,
    "layer":143, "total_layers":230,
    "nozzle":220, "nozzle_target":220, "bed":65, "bed_target":65,
    "chamber":41, "fan":100, "speed":"STANDARD", "light":"on",
    "ams":[{"type":"PLA","color":"#3fd8ff"},…],
    "hms":[{"attr":…,"code":…}], "print_error":0 } ] }

Client → server commands, acknowledged with {"type":"ack",…} or {"type":"error","detail":…}:

{ "type":"cmd", "id":"voyager01",
  "action":"pause|resume|stop|light|start_print|refresh",
  "on":true,                  // light only
  "file":"part.3mf" }         // start_print only
